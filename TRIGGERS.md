# Triggers

When to check a film against the project it describes, and what to call.

This file is written for an agent — a Claude Code / OpenCode skill, an MCP
host, anything choosing a tool on someone's behalf. Humans are welcome, but
the routing rules below are the point.

---

## The generalisation, stated once

> **A video that states a fact about a project is the trigger.** Nobody says
> "please verify my claims". They say "make a launch video", "update the demo
> reel", "the site video is out of date", « refais la vidéo », or they hand
> over a storyboard with a number in it. The moment a film asserts *how many*,
> *how fast*, *how much*, it has acquired a fact that will rot, and this is the
> tool that notices.

The second trigger is silent, and is the one to remember: **the project just
changed.** A catalogue grew, a package shipped, a module merged into another.
Nothing re-reads a rendered MP4 — so the film is now wrong and will stay wrong
until somebody looks. Run `verify_claims` after any change to the things a
film counts.

The third is narrow and concrete: **you are about to re-render.** Audit the
asset tree first. A render that fails halfway because a licensed music track
exists on exactly one disk is a worse discovery than the audit that said so.

---

## Which tool, and which neighbour

Several different questions get asked about the same film. Send each to the
right place — they do not substitute for one another:

| The question | Package | Tool |
|---|---|---|
| **Is it still true?** numbers, counts, quoted phrases | sprezzature-video | `verify_claims`, `scan_composition` |
| **Can it be rebuilt?** assets, narration, licensed media | sprezzature-video | `make-film assets` |
| **What does it say, in text?** captions, transcripts | sprezzature-video → sprezzature-audio | `build_captions` |
| **What goes in the frame?** charts, diagrams | sprezzature-figures | `make-figure` |
| **What goes in the frame, geographically?** | sprezzature-maps | `make-map` |
| **How does it sound?** narration, voices, diarization | sprezzature-audio | `sprezzature-audio-narrate-kokoro` |
| **How do the pixels move?** timing, animation, render | Hyperframes, behind the seam | not this package |

This package does **not** render. If the request is "make the video look
better", "add a transition", "animate this", it belongs to the renderer, not
here.

## The closed vocabulary

Route on these nouns, not on phrasings. When one appears **about a video**,
this package is in scope:

- **claim**, assertion, "it says", "on screen", number, count, "how many"
- **stale**, out of date, outdated, wrong number, drift, « périmé »
- **asset**, footage, music, narration, voice-over, licensed, "where did X come from"
- **re-render**, re-cut, rebuild, regenerate, « remonter »
- **caption**, subtitle, VTT, SRT, « sous-titres »
- **poster**, thumbnail, preview frame, "the image before you press play"
- **series**, formats, landscape / portrait / square, aspect ratio

Two of these route *out* rather than in: captions go through this package but
are written by `sprezzature-audio`'s VTT module, and narration is generated by
`sprezzature-audio[narrate]`. Say so rather than reimplementing either.

---

## What to call, in order

1. `verify_claims` — the declared claims against the code. Exit 1 means the
   film is lying; that is the gate.
2. `scan_composition` — every number visible on screen that no claim accounts
   for. Without this half, only the numbers somebody remembered to declare are
   protected, which is never the one that drifted.
3. `make-film assets` — can this be rendered again from a clone? Three classes:
   a copy away, a tool away, or nowhere else at all.
4. `build_captions` — from the narration script and the **measured** audio, not
   from a transcript and not from typed durations.

## When this package is the wrong answer

- **The video makes no factual claims.** A mood piece, a title sequence, a
  showreel. The apparatus here protects nothing.
- **The ask is motion design.** Particles, 3D, character animation: Remotion,
  Revideo, Hyperframes. See `LANDSCAPE.md`.
- **The ask is editing by hand on a timeline.** A declarative spec is the wrong
  shape for that work.
